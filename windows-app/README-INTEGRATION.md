# Windows 实机联调

解压 GitHub Actions 的 Windows x64 联调包。已安装 0.3.1 后端时直接双击 `MechrevoControl.Frontend.exe`。新装时右键 `Install.cmd` 并以管理员身份运行，旧版服务可双击 `Update.cmd` 更新。

确认窗口显示「实机」和当前硬件档位。记下起始档，点另一档并确认读回后切回。拔插电源可观察供电更新，关闭窗口后可以从托盘重新打开。服务断线时切档按钮禁用，旧快照标为过期。

使用 `--demo` 启动可进入演示场景和 OSD。0.2.1 从 Windows RAPL 计数器读取封装功耗，计数器预热后以瓦显示。0.3.0 增加 Dove4 Rev05 实机按键事件观察，托盘可开启本应用 OSD。实机启动时本应用 OSD 默认关闭。

用户确认 0.2.0 实机前端的切档、供电更新和托盘重开正常。0.2.1 的 RAPL 计数器已在目标机由后端代码单独读出 3.76–5.07 W，服务视角的显示待复核。

用户确认 0.2.1 的封装功耗已正常显示。0.3.0 的订阅、触摸板事件解析和状态回归在模拟命名管道上通过。验证目标机时，在原厂控制中心关闭原厂 OSD，从托盘开启本应用 OSD，再观察触摸板、键盘背光、Fn 锁的按键提示。麦克风和刷新率仅显示按键已收到，状态未确认。

实机确认触摸板和键盘背光按键均正确显示状态。原厂后台独立对照入口见 [功耗验证](../backend/oem-power-validation.md)。

0.3.1 在 Windows 睡眠和唤醒通知后作废旧快照，重新打开 RAPL 计数器与 WMI 事件监听。模拟睡眠和唤醒测试已确认服务实例维持、修订递增且功耗恢复。目标机用户确认正常睡眠唤醒后功耗刷新和背光 OSD 正常。当前联调目录可用 `Update.cmd` 更新后端。原厂后台独立功耗对照保留为单独验收。

## 0.3.1 实机联调包

本分支提供可解压运行的 [Windows x64 联调包](../backend/dist/Mechrevo-Control-0.3.1-win-x64.zip)。需要 x64 .NET 10 Desktop Runtime。这个包采用目标机的本地 Windows 构建和已验收二进制。GitHub Actions 工作流另有自包含构建配置。

解压后，新安装以管理员身份运行 `Install.cmd`，旧版运行 `Update.cmd`，日常用普通权限双击 `Start-Mechrevo.cmd`。从托盘菜单退出控制台。移除服务时先退出应用，再以管理员身份运行 `Uninstall.cmd`。

实机验收范围为 Dove4 Rev05。普通权限窗口、双向切档和恢复、插拔电源、电量、托盘、RAPL 封装功耗、触摸板与背光 OSD，以及睡眠唤醒后的功耗和背光提示已验证。原厂后台退出后的功耗对照属于独立实验。
