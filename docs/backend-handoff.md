# 无界 14 MAX 后端开发与联调计划

当前交付是设计。新对话可以从本文开始开发。目标是让普通权限 Windows 桌面 App 在机械革命无界 14 MAX 上读到真实状态、可靠切换平衡和性能、收到热键提示，并逐项接替原厂后台。首个可交付版本以两档切换的完整流程为准。其余能力独立验收。

适用基线为 Dove4 Lunar Lake、Core Ultra 7 256V、BIOS `WUJIE14Max_Dove4_LNL326_MC_OLED_Rev05`，原厂控制中心 5.56.1.24、EmOSDFunction 1.0.0.10。新机型或 BIOS 先探测可读能力，写入按已验证组合开放。

## 两个 agent 怎么合作

| 归属 | 交付和边界 |
|---|---|
| 后端 agent，兼任集成人 | Windows 服务、设备访问、热键解码、确有需要的用户会话动作、IPC 协议和实机客户端绑定、安装与恢复、联调与可运行版本。在主仓库开后端分支和 PR |
| 前端 agent | 桌面窗口、托盘、OSD、用户显示偏好、演示客户端和所有交互状态。在独立分支依照同一协议开发。OSD 关闭只影响提示，热键动作仍可工作 |
| 首次交接 | 后端先提交小型协议 PR，含字段定义、成功与失败样例、事件样例和协议版本。合入后两边从同一提交开始。前端告知客户端语言和适配器位置，两边在 PR 中约定该文件归属 |
| 最终交接 | 后端 agent 从合入两边代码的提交接通实机适配器，复用同一套页面，负责出包与说明。需要本机按键或观察硬件时，给用户一个明确操作并说明期望现象 |

建议目录为 `contracts/`（协议及共享样例）、`backend/`（服务和会话组件）、前端自有目录。已有前端结构优先沿用。原厂 MQTT 路径保留作研究依据，首版自有客户端直接连本机服务。

## 进程与设备边界

- **设备服务**建议使用 C# 和受支持的 .NET LTS，封装 Windows WMI/ACPI、供电、电池、遥测与 PnP。先验证服务身份实际拥有的读写权限。首次安装服务需要提升权限，日常 UI 使用普通用户权限。优先依赖 Windows 已绑定的 `wmiacpi.sys`，首版没有自写内核驱动的前置需求。
- **首版常驻两个进程**：一个普通权限前端 App（窗口、托盘、OSD）和一个后端 Windows 服务。用户会话动作由后端提供库，在现有托盘进程中执行。主窗口关闭后托盘继续处理当前用户的音频、显示和提示；切换用户或注销时清理会话订阅。
- 服务共享一次固件事件订阅和一份状态快照。性能页关闭时停止页面专用的高频遥测，切档优先于遥测。验收记录托盘空闲时两进程的合计工作集、CPU 占用和热键到 OSD 的延迟。
- **硬件访问**集中到按功能划分的适配器。保存数据来源、采集时间和最近确认值。睡眠恢复后重新发现活动 WMI 实例及设备，重建事件订阅，刷新能力和快照。某一传感器超时只影响该项。
- **原厂共存**从只读和观察事件开始。同一热键只设一个动作执行方；触摸板由固件处理，收到事件只刷新状态。麦克风等由原厂程序执行的动作，在确认原厂处理方已退出且新处理方接管以后开放。记录原厂组件运行状态，测试结束能恢复。

## V1 客户端契约

沿用前端交接中的方法名。以下是待实现的约定，第一份协议 PR 应固化为机器可读的结构和样例。建议使用限定本机访问的 Windows 命名管道，双向 UTF-8 JSON，每行一条消息。端点限制为服务和获准的本机交互用户，按调用方身份检查写操作。服务仅接受已定义的业务命令。前端不需要了解 WMI 类名或字节布局。

| 接口 | 行为 |
|---|---|
| `getCapabilities()` | 按功能返回 `readable`、`writable`、可选值及不可用原因。能请求系统动作但不能确认最终状态时，明确标出确认方式。供电、会话或设备变化后刷新 |
| `getSnapshot()` | 返回时间戳、修订号、机型、当前档位、AC/电池、电量、充电状态和可用遥测。定义 W、MHz、% 单位，未取得的字段为 null，零值保留。原始风扇及温区读数带来源，允许单项过期 |
| `setPerformanceMode(mode)` | 只接受 balanced 或 performance。服务串行执行，先读现状，已在目标档时直接返回已确认值。写后限时读回，匹配才成功。超时报告结果未知并重新同步，客户端禁止自动重放写请求 |
| `subscribeStatus(listener)` | 对应状态订阅。事件含服务实例标识和单调递增修订号；重连或发现缺口时重新订阅并取完整快照，按修订号丢弃过时更新 |
| `subscribeHotkey(listener)` | 对应热键订阅。载荷含事件 ID、时间、已识别动作及可确认状态。重连后不补放历史动作。无法确认的状态保留未知 |

请求带协议主版本和 requestId，响应复用 requestId 并返回结果或结构化错误。首批错误覆盖服务离线（客户端产生）、版本不兼容、权限不足、能力不可用、设备忙、调用超时、写后读回不一致。并发客户端共享同一设备操作队列。服务重启后客户端重新获取能力，旧快照可标记为过期。协议样例至少覆盖平衡切性能成功、写入未开放、写后仍读回平衡，以及服务断线。

## 各功能的实施顺序和证据

| 功能 | 首次实现与开放条件 |
|---|---|
| 性能模式 | 通过活动的 `root\wmi` 实例读取 `EmdAcpi_PowerPlanMode.GetPowerPlanMode`。已验证输入 Data=0，返回数据偏移 2 为 1/2。独立核对 setter 的方法号和输入布局，双向切换并读回，最后恢复起始档位，再开放写能力。Windows 电源计划另列。本机双烤稳定约 17 W / 30 W 可用于交叉检查，不能作为固定 PL1、PL2 或写入值 |
| 电池、供电、性能遥测 | 从 Windows 已有来源读取 AC、电量、充放电、封装功耗和频率。分别处理无电池、计数器缺失与空值。两路风扇、EC 温区及 Type-C VBUS 先保留原始值，核对单位及含义后再供界面标注 |
| Fn、触摸板、麦克风、键盘灯事件 | 订阅 `OemWMIEvent.Force`，按实测映射解码。触摸板只观察；麦克风需在会话中确认音频端点和最终静音状态。亮度、音量、睡眠、飞行模式按现有 Windows/固件路径分别验证，未见 OEM 事件也可由系统处理。避免重复动作或双重提示 |
| 键盘背光、熄灯时间、Win 键锁 | 原厂 10 秒档熄灯及按键唤醒、锁 Win 键有效均有实测。分别确认独立设置途径、持久化位置、恢复方式。区分设置亮度与临时熄灯；按键唤醒后应恢复所选亮度 |
| Wi-Fi、蓝牙、摄像头、屏幕刷新率 | 按设备分别探测 Windows 能力。无线开关以系统实态读回。摄像头物理电控会触发 USB 退枚举，对 UI 报告可用性，设备缺失原因未知时保留未知。面板已观察到 60/120 Hz，设置前枚举当前显示模式并验证回退 |
| 充电限制、风扇手动控制 | 后续独立实验。原厂界面没有电池保护入口，现有两项充电方法读零。只有明确有效范围、原状态恢复、实测停充及重新开始充电后才开放阈值写入。风扇写入须先证明可恢复自动控制。首版均保持写能力关闭 |

## 独立切档验证（待执行）

目标是在原厂用户态组件退出后，用自建程序复现两档的实际功耗差异。先从本机固件和原厂调用核对写方法、输入布局、返回值与恢复原档的途径，再准备最小工具。保留 Intel IPF/DTT 和平台驱动。

| 轮次 | 操作及记录 |
|---|---|
| A 原厂基线 | 记录起始档位和组件状态。插电、固定 Windows 电源设置、持续同一 CPU＋核显双烤。通过原厂控制台按平衡 → 性能 → 平衡切换。每次记录时间、独立 WMI 读回的编号、负载和封装功耗曲线，取稳定后最后 30 秒均值 |
| B 独立切档 | 暂停原厂 UI、桥接、控制服务与热键程序并检查是否重启。保持供电、负载和采样方法一致。用最小工具重复相同顺序，独立读取编号并比较三段功耗 |
| A′ 恢复复核 | 恢复原厂组件。若两轮不一致，重复原厂基线，检查温度变化、负载波动和组件是否自行重启。结束后恢复起始档位 |

若 B 同时复现编号 1 → 2 → 1 和与 A 相近的低 → 高 → 低功耗变化，可支持本次开机会话中独立选档。约 17 W 和 30 W 是此前双烤的参考值。若只见编号变化，优先追原厂后台的额外动作。要验收长期替代，再在原厂用户态组件未启动的冷开机条件下复测，结束后恢复启动配置。

**功耗限制的归属仍待查。** 沿固件切档方法追踪字段写入与通知目标，对齐一次切档前后原厂后台和 Intel 平台组件可取得的诊断事件。优先寻找具体参数下发或策略选择的证据；只有档位、时间相关性和功耗曲线时，执行方继续标记为未知。

## 智能选档（独立切档验证通过后）

由现有后端服务根据供电、CPU 和核显的持续繁忙程度，在平衡和性能之间选择。升档与降档使用不同的持续时间，降档等待更久。离电默认偏向平衡，允许用户选择离电高负载升档。平衡档满载实测约 17 W，以封装功耗超过 20 W 作为升档条件会漏掉这种负载。

协议分别表达用户选择的策略和硬件读回的当前档位。例如用户选择“智能”，当前生效档位可以是“平衡”。硬件写接口仍只接受两个实际档位。用户手动选档即取消自动决策和待执行的自动写入。智能模式仅保留低频负载采样，写后读回，连续失败暂停并报告。验收覆盖短突发不升档、持续 CPU 或核显负载升档、持续空闲降档、离电偏好和手动接管。具体阈值与时间窗口留待实机测定。

## 开发里程碑与验收

1. **协议可交接。** 提交协议、示例和客户端行为说明。用同一组样例检查演示客户端和协议序列化结果；前端此时可独立开发。
2. **只读服务可用。** 在目标机安装服务，以普通权限客户端读取型号、供电、档位和电池快照。拔插电源、重启服务、睡眠恢复后状态重新同步；错误或缺失值可辨认。交付可独立运行的诊断入口，便于区分 UI 与设备问题。
3. **打通一次真实切档。** 原厂软件保留可恢复。记录初始档位，从 UI 请求另一档，用独立只读 WMI 查询核对，然后切回。验证快速连点、写入失败、断线时页面显示最后确认值和必要的过期提示。若 setter 尚未验证，发布只读预览并列明阻塞证据。
4. **热键和设备按项接替。** 按上表逐项交付，登记每项的动作执行方、状态来源、已测 BIOS 和原厂组件依赖。按一次只执行一次；关闭本应用 OSD 后动作仍生效；原厂程序未运行时复测需要替代的动作。
5. **合并、出包和恢复。** 集成人在 Windows 上构建前后端，打包服务、普通权限 UI 和所需会话组件，提供安装、启动、诊断、卸载与恢复原厂的简明步骤。分别验证新装、更新、卸载和服务异常。迁移以可恢复方式逐项停用原厂用户态组件；完成对应回归后才将组件列为可替代。产物附版本、目标机实测清单及仍只读的项目。

每个 PR 写明改动、验证环境、可复现结果与仍待真机确认的项目。研究口径以[实现底稿](dove4-implementation-reference.md)、[WMI 映射](dove4-wmi-map.md)、[热键与灯光](dove4-hotkeys-and-lighting.md)、[接口路径](dove4-interfaces.md)和[双烤实测](dove4-mode-measurements.md)为准。页面行为见[前端交接](frontend-handoff.md)。
