# Windows 控制台前端交接

为机械革命无界 14 MAX（Dove4、Intel Core Ultra 7 256V）构建一个简体中文 Windows 桌面控制台。界面采用独立设计，首版聚焦当前档位、实时状态和热键提示。前端可以先用演示数据开发，再通过一处接口接入实际设备后端。界面技术栈由前端实现选择。

## 首版页面和交互

| 区域 | 首版交付 | 数据或能力边界 |
|---|---|---|
| 概览 | 机型、供电方式、电量、充电状态、当前性能档位 | 原厂已验证的硬件档位只有「平衡」「性能」。供电与充电分别显示 |
| 性能 | 两个档位选项、CPU 封装功耗、频率；接入有可信单位的风扇、温度读数 | 模拟模式可演示完整切换。实机写入只有在后端报告可用时才启用。两路风扇与 EC 温区目前能读原始值，单位及传感器位置仍待核实 |
| 电池 | 电量、接通电源、是否充电及可用的充放电功率 | 原厂界面没有限充入口。首版可展示明确可解释的读数。上下限字段目前读到 0，阈值设置等待实际停充和恢复默认验证 |
| 热键与 OSD | 已验证事件对应的短提示，界面可预览提示和控制应用自身的提示显示 | 提示由后台通知或演示事件驱动。触摸板事件可能在动作已完成后才发出，收到通知时直接更新状态并显示提示 |
| 设备开关 | 有已确认后端能力时再显示可操作控件，例如键盘背光或 Win 键锁 | Wi-Fi、蓝牙、摄像头等可作为后续接入。摄像头隐私开关会让整个 USB 设备退枚举，设备断开时显示状态，控制能力由后端声明 |

首页尽量直接呈现当前状态和两档选择。可把电池详情、热键与 OSD 收在次级区域。使用 Windows 系统字体、键盘可达的焦点顺序和有文本含义的状态提示。已有双烤读数可作为演示数据的依据。功耗模块应标成「CPU 封装功耗」。17 W 和 30 W 是一轮双烤的持续实测值，界面中的实时读数不能从档位名称推算。

## 前后端接入约定

下列名称是供前端实现的建议接口。仓库当前的 PowerShell 文件用于研究采集，尚无可直接依赖的长驻设备服务或正式 IPC 格式。前端把访问集中到一个可替换的客户端，演示版和实机版共用该接口。

| 接口 | 数据约定 |
|---|---|
| `getCapabilities()` | 每项能力分别返回能否读取、能否设置及有效选项。能力信息可随连接和供电状态刷新 |
| `getSnapshot()` | 返回档位、供电、电池和可用的传感器读数，带采集时间。缺失字段用空值表示，功耗单位用 W、频率用 MHz、电量用 %。未校准的读数另带原始值和来源 |
| `setPerformanceMode(mode)` | 建议模式标识为 `balanced`、`performance`。调用后等真实读回再更新已生效档位，错误时保留最后确认的状态并显示原因 |
| `subscribeStatus(listener)` | 状态变化时通知 UI。后端重连后先重新取能力和快照 |
| `subscribeHotkey(listener)` | 报告可识别的事件和可用状态，供更新控件或显示 OSD。已有映射见热键记录 |

普通权限 UI 通过设备后端读取或控制。固件访问、方法编号、原始请求字节和返回值解码由后端封装。建议在演示版显著标注「演示数据」，实机状态显示采集时间。等待接入、未支持、权限不足、正在应用和操作失败应有各自明确的显示。未支持的控制项可隐藏，已有状态但无法更改时可只读呈现。

### 接入时已知的设备事实

- 性能档位的固件读取已在两档实测，`EmdAcpi_PowerPlanMode.GetPowerPlanMode` 的值 1 是平衡、2 是性能。Windows 自身的电源计划另有状态。
- 原厂按键事件已核对 Fn 锁、触摸板、麦克风和至少一个键盘背光档。原厂程序还会执行部分热键动作。首版接入时应明确哪一进程执行动作，避免执行两次。
- 原厂 OSD、背光计时、Win 键锁已有实测。首版的 OSD 设置应明确控制的是本 App 的提示。原厂设置联动需要独立验证。
- 实机后端优先复用 Windows 的 ACPI‑WMI、音频和显示能力。未验证的固件写入由能力门控。UI 可完整交付可演示的交互流程。

## 日用流畅策略接入

按[日用流畅档实机验证计划](dove4-daily-smooth.md)准备演示状态。后端声明能力后开放启用和恢复操作，分别显示应用策略与实际硬件档位，例如“日用流畅 · 硬件平衡档”。日用流畅在平衡档内改善交互；智能选档根据持续负载选择平衡或性能。两者分别验收。恢复失败时保留错误和最后确认状态。

## 交付和验收

1. 提交可启动的 Windows 桌面前端、运行说明和演示数据入口，启动演示不依赖管理员权限或目标笔记本。
2. 演示数据覆盖插电、离电、平衡、性能、传感器不可用、设置成功及失败。确认切档失败时已生效档位仍与最后一次读回一致。
3. 证明演示客户端和后续设备客户端能使用同一套页面。接入失败时，界面能说明原因并重试。
4. 页面支持键盘操作，OSD 能用演示事件触发和关闭。能力不支持、正在读回和读数为零可明确辨认。
5. 实机联调时用下方资料核对能力。前端验收与是否可卸载原厂后台分别进行。
