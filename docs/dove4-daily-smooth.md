# 日用流畅档实机验证计划

目标是在原厂平衡档上改善 Windows 桌面交互，让动画帧时间接近性能档，同时尽可能保留平衡档的空闲功耗。后端负责实验与策略实现，前端负责展示和操作。此项可与前端开发并行，也可在原厂手动选定平衡档后先行实验；自动选档处理持续负载，两项分别验收。

## 本机观察与待验证问题

用户报告 Core Temp 显示平衡档静置约 1 W、日用平均约 4 W，性能档静置约 4 W、日用平均约 10 W。用户在平衡档偶尔观察到 Windows 11 动画掉帧，性能档较流畅。这四个功率数值是用户观察的 CPU 功率读数；整机放电、实际刷新率、两轮工作负载和帧时间仍需同步核对。双烤的约 17 W / 30 W 描述持续负载，无法定位动画开头的延迟，亦无法解释空闲差值。原厂策略、核显与桌面合成路径、后台唤醒都仍是候选原因。

## 实验顺序

1. **对齐基线。** 先记录每档切换前后的实际刷新率，再固定相同的 120 Hz、供电状态、亮度、桌面内容、后台应用和采样周期。分别让桌面静置至读数稳定，记录相同时间窗的 Core Temp CPU 平均功率；离电可另记整机放电功率。空闲测量与详细跟踪分开进行，监控工具在各对照组保持一致。
2. **复现用户能感知的卡顿。** 选择一个稳定触发问题的动作，例如反复开关开始菜单。在平衡和性能两档重复相同次数，记录 DWM 帧时间和错过刷新周期的次数，单看动画开始的几帧。120 Hz 每个刷新周期约 8.3 ms。若固定刷新率后差异消失，优先验证刷新率偏好能否独立设置。
3. **平衡档内逐项试验。** 保存当前电源配置以及对应 AC/DC 原值。按系统版本及支持情况筛选 Windows 交互提示（PerfLatencyHint 或 LatencyHintEpp），每轮只改一项，重复动画、静置和固定日常操作，再恢复原值复测。记录修改值、观测结果和恢复结果。设置可以写入、读回仅说明配置已保存，行为变化还须用帧时间和耗电验证。
4. **无改善时按现象定位。** 对动画做一次短时 ETW 跟踪，查看 DWM、CPU 提交和 GPU 完成工作的先后关系。对性能档多出的空闲功耗，另查后台活动、处理器唤醒和可取得的深度空闲驻留时间。按证据选择下一项试验。
5. **验收后接入。** 在相同条件下重复对照，报告三种状态（原厂平衡、原厂性能、平衡加候选策略）的空闲平均功率、相同操作序列的能耗、错过刷新周期次数和用户手感。记录重复测试的波动；仅在帧时间改善可复现、空闲功耗接近平衡档且原设置能恢复时对该配置开放能力。具体阈值用本机基线确定。

## 前后端交付

- 后端在现有服务中负责能力探测、应用、读回、恢复与故障处理。先记录原值再修改，部分应用失败时恢复已经修改的项目。提供恢复原配置入口，覆盖服务重启后的恢复。验证阶段可用 AI 离线分析记录，日常执行使用已验证的配置。
- 前端通过共享契约读取“策略可用性、已应用策略、硬件实际档位”，提供启用和恢复操作。成功时可显示“日用流畅 · 硬件平衡档”。样例覆盖未验证、应用中、应用成功和恢复失败。在首次实现中，启用日用流畅策略时暂停智能选档；用户切往手动档或智能策略时先恢复本策略改动，再交接控制。
- 用户在真机上重复最容易触发卡顿的操作并反馈手感；采集、分析及回滚由后端 agent 负责。
